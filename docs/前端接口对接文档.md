# 前端接口对接文档

> 后端服务：`backend/desktopclaw/api/server.py`，默认端口 `3000`，监听 `127.0.0.1`。
> 启动：`python -m desktopclaw api --port 3000`（开发模式由 Electron 主进程自动拉起，见 `frontend/electron/main.js:35`）。

---

## 1. 端点一览

| Method | Path | 用途 | 前端调用方 |
|---|---|---|---|
| `GET`  | `/health`         | 健康检查（Electron 启动时轮询） | `electron/main.js:88` |
| `POST` | `/chat`           | 聊天（标准 JSON 或 SSE 流式） | `api/chat.js` |
| `GET`  | `/chat/stream`    | SSE 流式聊天（GET 参数版本，前端未使用） | — |
| `GET`  | `/feishu/events`  | 飞书事件订阅（SSE） | `api/feishu.js` |
| `POST` | `/audio/upload`   | 语音上传 → ASR → AI → TTS | `api/audio.js` |
| `GET`  | `/media/<file>`   | 媒体文件代理（TTS 生成的 MP3） | `<audio>` 标签的 `src` |
| `GET`  | `/settings`       | 读取持久化的人格/Provider 配置 | `api/settings.js` |
| `POST` | `/settings`       | 写入人格/Provider 配置 | `api/settings.js` |

所有响应均带 `Access-Control-Allow-Origin: *`，已支持跨域。

## 2. 详细字段

### 2.1 `POST /chat`

**Request body**（`application/json`）：
```jsonc
{
  "message": "string",            // 必填
  "channel": "api",               // 可选，默认 "api"
  "modelId": "string?",           // 可选，覆盖配置默认模型
  "apiKey":  "string?",           // 可选，覆盖 Provider api_key
  "baseUrl": "string?",           // 可选，覆盖 api_base
  "personality":  "gentle|active|tsundere?", // 可选
  "customPrompt": "string?"       // 可选，原样作为 system 前置注入
}
```

**两种响应模式**（由 `Accept` 头决定）：

- **标准 JSON**（默认）：
  ```json
  { "success": true,  "response": "string" }
  { "success": false, "error":    "string" }
  ```

- **SSE 流式**：当请求头包含 `Accept: text/event-stream` 时，逐 chunk 推送以下事件：

  | `type` | 字段 | 含义 |
  |---|---|---|
  | `thinking`  | `content` | "AI 正在思考..." 占位 |
  | `progress`  | `content` | 进度文本（agent 阶段、子任务标题等） |
  | `tool_call` | `content` | 工具调用名称（按 `channels.send_tool_hints` 配置） |
  | `complete`  | `response` | 最终回复全文，流即将关闭 |

  帧格式：`data: <json>\n\n`，UTF-8。前端解析见 `frontend/src/api/stream.js`。

⚠️ **重要**：SSE 流必须由渲染进程直连后端（`fetch` + `ReadableStream`）。Electron 主进程的 `send-message` IPC 通道仅代理标准 JSON 模式（`electron/main.js:289`）。

### 2.2 `POST /audio/upload`

**Request**：`multipart/form-data`，字段：
- `audio`：音频 Blob（默认 `audio/webm`）
- `channel`：字符串，默认 `feishu`

**Response**：
```jsonc
{
  "success": true,
  "transcription": "string?",     // ASR 结果
  "response":      "string?",     // AI 回复
  "ttsAudio":      "string?"      // /media/xxx.mp3 完整 URL，可直接喂 <audio src=...>
}
```

> ASR 走阿里云 DashScope `qwen3-asr-flash`，TTS 走 `qwen3-tts-flash`，需在 `~/.nanobot/config.json` 的 `channels.feishu.asrApiKey` 配置 key（或在前端"设置"中设置；当前未在前端开放此项）。

### 2.3 `GET /feishu/events`

无 body 的 SSE 端点。事件 `type`：

| `type` | 字段 | 含义 |
|---|---|---|
| `inbound`   | `content`, `senderId`, `chatId`, `media?`, `metadata?`, `msgId`, `msgType` | 飞书入站消息 |
| `outbound`  | `content`, `chatId` | 后端发往飞书的出站消息（前端可同步显示） |
| `heartbeat` | — | 30s 一次的保活帧 |

前端使用方式：`api.feishu.connectFeishuEvents(onEvent)`，返回 `disconnect()`。Electron 优先走 IPC，浏览器回退到 `EventSource`。

### 2.4 `GET /settings` / `POST /settings`

均使用 **camelCase** 字段（与磁盘 `~/.nanobot/config.json` 的 alias 一致）。

**Response shape（GET）/ Body shape（POST，所有字段可选）**：
```jsonc
{
  "baseUrl":      "string",
  "modelId":      "string",
  "apiKey":       "string",
  "personality":  "gentle|active|tsundere",
  "customPrompt": "string",
  "birthday":     "YYYY-MM-DD",
  "feishu": {
    "asrEnabled": true,
    "ttsEnabled": true,
    "ttsVoice":   "Cherry"
  }
}
```

POST 仅写入白名单字段（其它字段被忽略），通过 `load_config → 修改 → save_config` 持久化到 `~/.nanobot/config.json`。前端 `useSettings.save()` 同时写 localStorage 与后端，确保离线时仍有最近一次配置。

### 2.5 `GET /media/<filename>`

直接读取 `get_media_dir("feishu")` 下的文件。`Content-Type` 由后缀推断：`.opus → audio/ogg; codecs=opus`，`.mp3 → audio/mpeg`。前端用于 `<audio src="...">`。

## 3. 前端 API 层使用规范

```js
// 聊天（推荐：流式）
import { streamMessage } from '@/api/chat'
import { useSettings } from '@/stores/useSettings'

const settings = useSettings()
await streamMessage(
  '你好',
  settings.chatOptions.value,
  (event) => {
    if (event.type === 'complete') console.log(event.response)
  },
)

// 设置
import { fetchSettings, saveSettings } from '@/api/settings'
const remote = await fetchSettings()
await saveSettings({ personality: 'tsundere' })

// 飞书 SSE
import { connectFeishuEvents } from '@/api/feishu'
const disconnect = await connectFeishuEvents((e) => console.log(e))
// 在 onUnmounted 调用 disconnect()
```

**新增端点的步骤**：
1. 在 `backend/desktopclaw/api/server.py` 的 `handle_request` 添加路由分支。
2. 在 `frontend/src/api/` 新增模块（参照 `chat.js` / `settings.js`）。
3. 在 `frontend/src/api/index.js` re-export。
4. 不要绕开 `request.js` 的 axios 实例 —— 它统一处理 baseURL、Bearer 头、错误归一。

## 4. 错误处理约定

`api/request.js` 抛出 `ApiError`，含 `kind` 字段：

| `kind` | 触发条件 | 建议 UI |
|---|---|---|
| `network`  | 后端不可达 | "网络连接失败，请确认后端服务已启动" |
| `timeout`  | 超过 10 分钟 | "请求超时，请稍后重试" |
| `http`     | 非 2xx       | 显示 `error.message`（已含状态码） |
| `business` | `success: false` | 显示 `error.message`（已含 server `error` 字段） |
| `unknown`  | 其它 | 兜底 |

调用方既可以 `try/catch ApiError` 分支处理，也可以让其上抛由 `useChat` 的兜底逻辑展示在对话气泡里。
