## 2. 分层职责

```
┌──────────────────────────────────────────────────────────┐
│  components/*.vue       —— 只关心 props/emit/模板         │
│              ↓ 调用                                       │
│  stores/use*.js         —— 跨组件单例状态                 │
│  composables/use*.js    —— 局部行为（每实例独立）         │
│              ↓ 调用                                       │
│  api/*.js               —— HTTP/SSE 调用，归一错误         │
│              ↓ 通过                                       │
│  api/request.js         —— axios 实例 + 拦截器             │
└──────────────────────────────────────────────────────────┘
```

**禁止**：
- 组件中直接 `fetch` / `axios.post` —— 必须经 `api/`。
- `api/` 中直接读写 ref —— 应只接受 plain object 入参，返回 plain data。
- `stores/` 中持有 DOM ref 或 PIXI 实例之外的副作用资源（除非有 `cleanup`）。

## 3. 命名约定

| 类型 | 文件名 | 导出 |
|---|---|---|
| Vue 组件 | `PascalCase.vue` | default export |
| Store | `useXxx.js`，导出 `useXxx()` 返回普通对象 | 命名导出 |
| Composable | `useXxx.js`，每次调用返回新实例 | 命名导出 |
| API 模块 | `xxx.js` 业务名 | 命名导出 |
| 数据 | 普通名词 `xxx.js` | 命名导出 |
| Utils | 普通动词/名词 `xxx.js` | 命名导出 |

## 4. 添加新组件的步骤

1. 在 `components/` 新建 `MyComponent.vue`，使用 `<script setup>`。
2. 引入需要的 store / composable / api，**不要**直接把状态从父组件传一长串 props 进来。
3. 样式：

   - 与已有 UI 风格一致：写在 `App.vue` 的全局 `<style>` 中（避免 scoped 把跨组件类隔离掉）。
   - 仅当前组件私有：在组件文件里写 `<style scoped>`。

4. 在 `App.vue` `<template>` 中以语义槽位插入并传入受控 props（visibility / size 等）。

## 5. 添加新接口的步骤

1. **后端**：在 `backend/desktopclaw/api/server.py` 的 `handle_request` 加路由分支与 handler 方法。如需配置持久化，遵循 `_handle_set_settings` 的白名单写入模式。
2. **前端**：在 `frontend/src/api/` 新建模块或扩展现有模块；在 `index.js` re-export。
3. **集成**：通常包一层 store 方法（如果状态需要跨组件共享）或 composable（如果只在一处使用）。

## 6. 风格与本次重构遗留

- 已统一：消息 `role` 仅用 `'user'` 与 `'ai'`（移除了原代码中 `'assistant'` 的误用）。
- 已修复：`scheduleDailyReminders` 不再每次触发就递归重排全天，改为按时间槽逐个推进。
- 已抽取：「移除 thinking 占位」的逻辑统一在 `useChat.resolveThinking()`。
- **personality 限制**：后端 `LiteLLMProvider.chat` 仅识别 `gentle/active/tsundere` 字面量，扩展时需同步后端代码。
- **林翩翩模型**：代码引用但 `public/` 缺资源，已从 fallback 列表移除；如需保留请补回 model3 资源。

## 7. 调试提示

- Electron 主进程日志会被前缀 `[Electron]` / `[Backend]` 输出到 stdout。
- 前端 `console.log` 在 Electron 中通过 `console-message` 事件转发到主进程（参见 `electron/main.js:175`），但仅以 `[Frontend]` 开头的日志会被打印。
- 后端 SSE 调试：`curl -N -H 'Accept: text/event-stream' -X POST http://127.0.0.1:3000/chat -d '{"message":"hi"}'`。
- 配置往返：`curl http://127.0.0.1:3000/settings`，写入用 `curl -X POST -d '{"personality":"active"}' -H 'Content-Type: application/json' http://127.0.0.1:3000/settings`，再次 GET 验证。
