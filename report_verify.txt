 56 [Heading 1] 1 绪论
 57 [Heading 2] 1.1 目标软件系统开发的目的和意义
 58 [Body Text] 随着大语言模型（LLM）技术的快速发展，个人用户对本地化、可定制、可扩展的 AI 助手需求日益增长。传统在线聊天机器人难以满足桌面常驻、多渠道接入、工具调用与长期记忆等复合场景。DesktopClaw
 59 [Body Text] 本系统的开发目的包括：（1）提供基于 Electron + Vue 3 的桌面交互界面，支持 Live2D 虚拟形象与独立聊天窗口；（2）构建 Python 异步后端，实现流式对话、工具调用、子代理调
 60 [Heading 2] 1.2 开发工具及相关技术介绍
 61 [Body Text] 本项目采用前后端分离的全栈架构，主要开发工具与技术如下：
 62 [List Paragraph] 后端：Python 3.11+、asyncio HTTP 服务、Pydantic 配置校验、LiteLLM 多模型调用；
 63 [List Paragraph] 前端：Vue 3、Vite、Electron 28、PIXI.js + Live2D Display 桌面宠物渲染；
 64 [List Paragraph] 通信：HTTP REST、SSE 流式推送、Electron IPC、WebSocket（Bridge 层）；
 65 [List Paragraph] AI：AgentLoop 引擎、ToolRegistry 工具注册、MCP 协议、Skills 技能系统；
 66 [List Paragraph] 记忆：sentence-transformers 本地嵌入、SQLite 图存储、Reasoning Bank 策略库；
 67 [List Paragraph] 测试：pytest + pytest-asyncio（48 个测试文件）、Ruff、electron-builder。

 75 [Heading 1] 3 需求分析
 76 [Heading 2] 3.1 功能需求
 77 [Body Text] 根据项目实现，系统功能需求归纳如下：
 78 [List Paragraph] 桌面宠物：Live2D 形象、窗口拖拽缩放、鼠标穿透、控制按钮；
 79 [List Paragraph] 聊天对话：POST /chat 与 SSE /chat/stream，多轮上下文与工具调用展示；
 80 [List Paragraph] 会话管理：会话列表 CRUD、历史消息加载；
 81 [List Paragraph] 记忆管理：用户事实与 Agent 策略双域存储及 API 查询；
 82 [List Paragraph] 设置配置：LLM Provider、API Key、模型与人格模板；
 83 [List Paragraph] 工具能力：文件读写、Shell、深度网络研究、定时任务、子代理；
 84 [List Paragraph] 多渠道：Telegram、飞书、钉钉、Discord、Slack、QQ、微信、Email、Matrix、WhatsApp 等；
 85 [List Paragraph] 媒体处理：音频上传与媒体文件访问。
 86 [Heading 2] 3.2 性能需求
 87 [List Paragraph] 流式响应：SSE 首 token 延迟取决于 LLM 提供商，目标低于 3 秒；
 88 [List Paragraph] 上下文窗口：默认 65536 tokens，超长会话触发记忆归档；
 89 [List Paragraph] 并发处理：asyncio 异步 I/O，消息总线队列化处理；
 90 [List Paragraph] 深度研究：deep_web_search 默认超时 120 秒，可配置并发与页数；
 91 [List Paragraph] 记忆检索：向量 + 图遍历混合，索引由 MemoryIndexWorker 异步维护。
 92 [Heading 2] 3.3 软件开发约束需求
 93 [List Paragraph] 运行环境：Windows 10+，Python ≥ 3.11，Node.js 用于前端构建；
 94 [List Paragraph] 本地绑定：API 默认监听 127.0.0.1:3000；
 95 [List Paragraph] 安全约束：Shell 受 ExecToolConfig 限制，文件操作可 restrict_to_workspace；
 96 [List Paragraph] 配置管理：Pydantic Schema 统一校验；
 97 [List Paragraph] 依赖可选：memory、web-search 等通过 extras 安装。
 98 [Heading 2] 3.4 软件质量要求
 99 [List Paragraph] 可维护性：模块化目录，各渠道继承 BaseChannel；
100 [List Paragraph] 可测试性：pytest 覆盖 Agent、记忆、渠道、API 等 48 个模块；
101 [List Paragraph] 可扩展性：ToolRegistry 插件、Skills 热加载、MCP 动态接入；
102 [List Paragraph] 安全性：DOMPurify 防 XSS、路径穿越防护、allow_from 白名单；
103 [List Paragraph] 可用性：/health 健康检查、友好错误提示、Usage 令牌追踪。
